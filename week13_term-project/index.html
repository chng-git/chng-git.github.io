개요 및 목적

📌 개요

외부 기상 데이터(강수량 등)와 AI 기반 이상 패턴 분석 및 보조 로그 생성에 따라 자산의 이동이 안전하게 제어되는 조건부 스마트 컨트랙트 시스템 구축.

🎯 목적 (문제 제기)

  • 기존 단일 오라클 의존 시 발생하는 단일 장애점(SPOF) 위협 극복.
  • 온체인 연산을 최소화하여 가스비를 절감함과 동시에, 오프체인 미들웨어에서 다중 합의 및 생성형 AI(LLM) 환경 분석을 융합하여 보안성을 극대화.

기획의 진화: Security-First 아키텍처 고도화

개발 과정에서 발견한 치명적인 보안 취약점을 주도적으로 방어하기 위해 시스템을 진화.

📉 초기 기획 (제안서)

단일 장애점(SPOF) 리스크 내포

  • 단일 API (OpenWeatherMap) 의존
  • 단순 AI 데이터 이상치 탐지 로직
  • 중앙화된 오프체인 실행 방식
➔

🛡️ 최종 구현 (하이브리드 보안)

취약점 원천 차단 및 보안 완성

  • 다중 오라클 합의 : OpenWeather API 기반 프로토타입 구현 및 추가 API 연동 교차 검증
  • 리플레이 공격 방어 : ECDSA 서명 & 1회용 OTP 도입
  • AI 기반 위험 분석 : 최신 Gemini 2.5 Flash를 통한 개방 위험도 정성적 분석

기술 스택

Smart Contract(온체인) Solidity (0.8.20), OpenZeppelin (ECDSA)
Infrastructure(배포 및 테스트) Hardhat, Sepolia Testnet, MetaMask
Middleware(오프체인 서버) Node.js, Ethers.js (서명 및 블록체인 통신), Axios
Data & AI(오라클 및 위험도 분석) OpenWeatherMap API, wttr.in, Google Gemini 2.5 Flash API

프로젝트 핵심 코드 구조

📜 WeatherSecureVault.sol (온체인)
금고의 핵심 제어부. 외부 미들웨어에서 전달된 서명을 ECDSA로 검증하고, 재전송 공격을 방어하며 조건이 충족될 때만 자산 상태를 업데이트합니다.
🤖 weather.js (오프체인 미들웨어)
다중 API(날씨) 교차 검증 및 AI(Gemini) 위험도 분석을 수행한 후, Ethers.js를 통해 오라클 권한으로 암호학적 서명을 생성하여 컨트랙트에 전송합니다.
🚀 deploy.js (인프라)
작성된 컨트랙트를 Hardhat 환경을 통해 Sepolia 테스트넷에 안전하게 배포하고, 초기 오라클 권한(signer)을 설정하는 배포 스크립트입니다.

온체인 핵심 로직: WeatherSecureVault.sol

무결성을 유지하기 위한 3단계 방어벽(Require) 구조

function updateWeatherState( bool isRaining, uint256 timestamp, bytes memory signature ) {
  // 1. 시간차 공격 방어 (미래 시간 조작 불가)
  require(timestamp <= block.timestamp, "Future time!" );

  // 2. 리플레이 공격 방어 (1회용 서명 확인)
  bytes32 sigHash = keccak256(signature);
  require(!usedSignatures[sigHash], "Signature already used!");

  // 3. 인가된 서버 서명 검증 (ECDSA.recover)
  require(recoverSigner(hash, signature) == oracleNode, "Invalid!");

  usedSignatures[sigHash] = true; // 서명 소각 처리 (OTP)
}

구현 1: 인프라 구축 및 타임스탬프 동기화

목표: 스마트 컨트랙트 기초 배포 및 오프체인 미들웨어 연동

  • 이슈 1 (환경 충돌): 초기 Hardhat v3 ↔ v2 환경 충돌 및 의존성 문제 발생
    • [해결] Hardhat v2 체제로 환경 재구성 및 의존성 해결.
  • 이슈 2 (시간차 공격 방어망 오작동): Sepolia 배포 시 Future timestamp not allowed 에러 발생.
    • [해결] 오프체인 서버에서 Date.now() - 60초로 타임스탬프 버퍼 부여.
💡 [이미지] 해결 전 튕겨 나갔던 에러 로그 화면

구현 2: 하이브리드 보안 아키텍처

  • 다중 오라클 합의 (Consensus): 두 API의 데이터를 교차 검증하여 모두 합의를 이룰 때만 트랜잭션 발생.
  • 암호학적 서명 검증: ECDSA recover() 기반 서명 검증을 통해, 사전에 승인된 오라클 서버에서 전송한 데이터만 온체인 기록을 허용.
  • 리플레이 공격(Replay Attack) 방어:
    • 온체인에 usedSignatures 매핑을 추가하여 서명을 1회용(OTP)으로 강제.
    • [결과] Signature already used! 에러 반환 및 완벽 차단.
💡 [이미지] 터미널 해커 차단 성공 로그
💡 [이미지] Etherscan 성공/Revert 기록

구현 3: AI 기반 환경 위험도 분석 및 로그 생성

목표: 하드웨어 금고의 물리적 개방 위험도를 AI가 정성적으로 분석.

  • 이슈 (AI 라이프사이클 종료): Gemini 구형 모델(1.5-flash) 서비스 종료로 404 에러 발생.
    • [해결] 최신 활성 모델인 gemini-2.5-flash로 마이그레이션 적용.
💡 [이미지] AI의 개방 경고 로그 캡처

취약점 및 보완점 (Risk & Future Work)

  • 오프체인 미들웨어의 중앙화: 다중 오라클 합의를 단일 Node.js 서버가 전담함. 향후 Chainlink 분산형 오라클 네트워크(DON)를 연동하여 탈중앙화 수준을 높여야 함.
  • AI의 비결정성(Non-deterministic) 한계: 현재는 AI 분석을 오프체인 '모니터링 로그'로 활용 중이나, 향후 AI 분석 결과를 스마트 컨트랙트 조건 로직과 안전하게 연동하기 위한 추가 연구 필요함.

마무리 (Conclusion)

  • 블록체인이 현실 데이터와 연결될 때 발생하는 본질적 취약점(오라클 조작, 가스비, 리플레이 공격)을 직접 식별하고 방어함.
  • 최신 생성형 AI를 결합한 하이브리드 인프라를 통해, 보안성과 실용성을 모두 갖춘 차세대 스마트 컨트랙트의 가능성을 입증.
